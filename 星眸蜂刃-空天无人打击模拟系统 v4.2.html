AI 调度算法讲解

星眸蜂刃 · 任务分配模块 —— 贪心 + 优先级排序

一、问题定义

给定已侦察目标集合 T（每个目标带威胁等级与距基地距离），以及有限弹药池（蜂群单元数量 B）。要求在弹药约束下，为每个目标分配蜂群单元，使高价值目标优先获得打击资源。

二、调度策略（两层排序 + 贪心分配）

  • 第一优先级：威胁等级降序 —— 高威胁（导弹发射车/指挥所/雷达站）> 中威胁（装甲集群/防空阵地）> 低威胁（补给车队/通信基站），确保"打要害"。
  • 第二优先级：距离升序 —— 同等级目标按距基地由近及远，减少突防暴露时间，提高任务成功率。
  • 贪心弹药分配 —— 按排序依次为目标分配需求弹药（默认 高 8 架 / 中 5 架 / 低 3 架，可在「打击规模设置」中现场调整）；首轮弹药池 = Σ需求 + 15% 余量，因此默认配置下每个目标都能满足（演示"弹药充足时的优先级排序"）；把规模拉到弹药池无法覆盖时，贪心算法会优先保障威胁等级高、距离近的目标，后续目标标记"弹药不足·未分配"。

三、伪代码

function 任务分配(T, B): # T: 目标集合, B: 弹药池 # ① 威胁等级降序（高>中>低） T ← sort(T, key=威胁等级, desc) # ② 同等级按距离升序（近优先） T ← sort(T, key=距离, asc) A ← 空表 # 分配表 for 目标 in T: # ③ 贪心分配 need ← 需求弹药(目标.威胁) # 默认高8/中5/低3，可自定义 if B ≥ need: A[目标] ← need; B ← B − need else if B > 0: A[目标] ← B; B ← 0; 标记"弹药不足" else: A[目标] ← 0; 标记"弹药不足" # 首轮弹药池 B = Σ需求 + 15%余量；补击弹药池另按补击倍数预留 return A # 输出分配表

四、备选算法：加权评分排序（现场对比）

把「威胁等级 / 目标价值 / 距离」折算成同一量纲打分后整体排序，取代两级排序：

function 优先级(目标): score ← 40 × 威胁权重 # 高 1.0 / 中 0.65 / 低 0.35 score ← score + 30 × (价值 / 最高价值) score ← score + 30 × (1 − 距离 / 400km) return score T ← sort(T, key=优先级, desc) # 加权评分降序 # 分配步骤与贪心完全相同：需求 ← 打击规模(威胁)

两种排序的差别：贪心是「字典序」（威胁绝对优先），加权评分允许高价值近距目标反超低威胁目标。现场可用本局真实数据对比下方结果。

五、复杂度与讨论

  • 时间复杂度：排序 O(n log n) + 贪心遍历 O(n)，适合战场实时调度。
  • 贪心策略得到的是局部最优：保证排序靠前的高价值目标优先，但极端情况下可能使低价值目标无弹药可用。实战中可通过迭代加深、市场竞拍等算法进一步全局优化。
  • 现场演示要点：观察"高威胁近距"目标如何优先获得蜂群，以及弹药耗尽时低威胁目标的"弹药不足"标记。
  • 两种排序算法在本局的差异见上方「本局算法对比」；若两者一致，说明本局威胁等级与价值/距离的取向没有冲突。
